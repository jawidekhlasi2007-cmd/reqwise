# Спецификация требований к программному обеспечению
## Уведомления о месячном лимите расходов — мобильный банк

Версия 0.9 (черновик)

## 1. Введение

### 1.1 Назначение
Документ описывает функцию, которая позволяет розничным клиентам установить месячный лимит расходов в мобильном приложении банка и получать уведомления при приближении к лимиту и его достижении.

### 1.2 Границы
Функция включает настройку лимита, учёт расходов, push-уведомления и соответствующий API. Выпуск карт и АБС не входят в рамки документа.

## 2. Функциональные требования

ФТ-1. Клиент должен иметь возможность установить месячный лимит расходов в мобильном приложении.
Критерий приёмки: лимит сохраняется.

ФТ-2. Лимит по умолчанию составляет 50 000 KZT.

ФТ-3. Система должна быстро отправлять push-уведомление, когда клиент достигает лимита.

ФТ-4. Предупреждение отправляется при расходовании 90% лимита.

ФТ-5. Уведомление должно содержать сумму покупки, остаток лимита и текущий баланс счёта.

ФТ-6. Расходы учитываются по всем картам клиента.

ФТ-7. Лимит обнуляется в начале каждого месяца.

ФТ-8. Клиент может изменять лимит не чаще одного раза в день.

ФТ-9. Если уведомление не доставлено, система должна повторить отправку.

ФТ-10. Клиент может отключить уведомления.

ФТ-11. Экран настройки лимита должен быть удобным и интуитивно понятным.

ФТ-12. Клиент может установить лимит от 1 000 до 10 000 000 KZT.

ФТ-13. Клиент должен иметь возможность задать месячный лимит расходов в мобильном приложении.

## 3. Нефункциональные требования

НФТ-1. Система должна выдерживать высокую нагрузку.

НФТ-2. Уведомление должно отправляться в течение 5 секунд.

НФТ-3. Данные клиента должны быть защищены.

НФТ-4. Доступность сервиса должна составлять 99%.

## 4. API

API-1. `POST /api/v1/limits` устанавливает лимит. Тело запроса: `{ "customerId": "...", "amount": 50000 }`. Возвращает 200 `{ "status": "ok" }`. При ошибке эндпоинт также возвращает 200 с полем `error`.

API-2. `GET /api/v1/limits/{customerId}` возвращает лимит, сумму расходов и баланс счёта.

API-3. `POST /api/v1/notifications/send` отправляет уведомление клиенту. Используется сервисом процессинга.

## 5. Интерфейс

UI-1. На главном экране отображается индикатор использования лимита. Предупреждение показывается при 80% лимита.

UI-2. Индикатор становится красным при превышении лимита.

## 6. Логирование

LOG-1. Все запросы к API логируются полностью, включая тело запроса и номер карты, чтобы упростить разбор инцидентов.
